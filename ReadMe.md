# Hotel PMS Room Auto-Assignment Engine

실제 비즈니스/시티 호텔의 층별 물리적 건축 레이아웃과 도메인 규칙을 정밀하게 모델링하고, **2-Pass 파이프라인(Hard Filter + Soft Scoring)**, **우선순위 기반 대량 배치 배정(Batch Assigner)** 및 **Google Gemini AI 기반 다국어 자연어 요청 배치 파싱**을 결합한 Java 기반 차세대 PMS(Property Management System) 코어 엔진입니다.

---

## 1. 프로젝트 개요 (Overview)

* **개발 환경**: Java 21+ (Gradle)
* **아키텍처 원칙**: 순수 도메인 주도 설계(DDD) 지향, 단일 진실 공급원(Single Source of Truth) 보장, AI 추론 계층과 코어 도메인 배정 엔진의 완전한 책임 분리
* **핵심 목표**:
  1. 결번(서구권 금기 번호, 설비실) 및 층별 특수 구조를 반영한 **실제 호텔 도면(총 191실) 완벽 매핑**
  2. 오버부킹과 환각(Hallucination)을 원천 차단하는 **불변 계약 검증(Hard Filter)**
  3. 고객 선호도 및 체류 기간(Long-stay)에 기반한 **다차원 채점 엔진(Soft Scoring)**
  4. 다국어(한국어, 일본어, 영어) 비정형 요청 메모를 단 1회의 LLM 호출로 정제하는 **배치 AI 파이프라인(`parseBatch`)**
  5. 사전 재실(Checked-in) 객실 상태를 고려한 **우선순위 기반 50건 대량 일괄 배정(Batch Allocation)**

## 2. 객실 물리 구조 및 도메인 사양 (Room Specs)

3층부터 15층까지 총 13개 객실 층으로 구성되며, 서양권 금기 번호 및 설비 배치를 고려한 결번 규칙을 적용하여 **총 191실**을 유지합니다.

### 층별 및 호실 구성표
| 구분 | 해당 층 | 층당 호수 범위 | 결번 규칙 | 실질 객실 수 |
| :--- | :--- | :--- | :--- | :--- |
| **일반 객실층** | 3층 ~ 13층 (11개 층) | 01호 ~ 16호 | **13호 전 층 결번** (서구권 금기 번호) | 15실 × 11 = **165실** |
| **상층부 특수층** | 14층 ~ 15층 (2개 층) | 01호 ~ 16호 | **13호 결번** + **03호, 07호 추가 결번** (설비 배치) | 13실 × 2 = **26실** |
| **총계** | **13개 층** | - | - | **총 191실** |

### 호실별 타입 및 물리 속성 매핑
* **`01호, 14호`**: 슈페리어 트윈 (`SUPERIOR_TWIN`)
* **`02호, 09호`**: 레지덴셜 더블 (`RESIDENTIAL_DOUBLE`)
* **`05호, 06호, 10호, 11호`**: 슈페리어 더블 (`SUPERIOR_DOUBLE`)
* **`04호, 08호`**:
  * 13층 이하: 모더레이트 더블 (`MODERATE_DOUBLE`)
  * 14층 이상: 이그제큐티브 더블 (`EXECUTIVE_DOUBLE`)
* **`12호, 15호, 16호 및 03호, 07호(일반층)`**: 모더레이트 더블 (`MODERATE_DOUBLE`)
* **엘리베이터 인접 구역**: `03호 ~ 08호` (보행 약자 접근성 우수 / 소음 취약 구역)
* **코너룸 구역**: `01호, 02호, 09호, 14호, 16호` (측면 창문 보유, 외부 소음 최소화)

## 3. 핵심 배정 알고리즘: 2-Pass Pipeline

객실 배정은 안전성을 보장하는 **절대 규칙 검증**과 고객 만족도를 극대화하는 **선호도 기반 최적화** 단계로 구성됩니다.

```text
[인입된 예약 (Reservation)]
       │
       ▼
┌────────────────────────────────────────────────────────┐
│ 1-Pass: Hard Filter (물리적 제약 조건 검증)             │
│  - 예약 객실 타입 일치 여부 (RoomType Match)           │
│  - 현재 미배정/공실 여부 (Not Assigned)               │
│  - 기존 재실(Occupied) 및 체크인 상태 충돌 방지       │
└────────────────────────────────────────────────────────┘
       │ (통과된 후보 객실군)
       ▼
┌────────────────────────────────────────────────────────┐
│ 2-Pass: Soft Scoring (다차원 선호도 가중 채점)         │
│  - 층수 선호: HIGH(+10), LOW(+10)                      │
│  - EV 동선: AWAY(+10), NEAR(+10)                       │
│  - 코너 선호: PREFER(+10), AVOID(+10)                  │
│  - 정숙도(Quiet): 소음 격리 가산점(+15)                │
│  - 연박 가중치: stayNights × (1 + score × 0.1) 반영     │
└────────────────────────────────────────────────────────┘
       │
       ▼
[최적 객실 확정 (Best Matching Room)]
```

## 4. 대량 배치 배정 및 우선순위 큐 (Batch Allocation)

단순 FIFO(선착순) 방식의 배정 시 발생하는 객실 조기 소진 및 만족도 저하 문제를 방지하기 위해 **`BatchAssigner`**를 도입했습니다.

1. **우선순위 정렬 (Sorting Strategy)**:
   * **1순위 (연박)**: 투숙 기간이 긴 장기 숙박객 우선 (중간 객실 이동/청소 리스크 최소화)
   * **2순위 (요청 난이도)**: 요구 조건이 까다로운(층수, EV 이격, 코너 등 다중 조건) 예약 우선
   * **3순위 (인입 순서)**: 동일 조건 시 예약 ID 기준 정렬
2. **사전 재실 객실 격리**:
   * 이미 체크인되어 투숙 중인 객실(Checked-in)을 인벤토리에서 실시간 잠금 처리한 후 신규 배정을 수행합니다.

## 5. AI 다국어 자연어 분석 파이프라인 (Gemini Batch Engine)

다국어 비정형 요청 메모(한국어, 일본어, 영어, 특수 요청 등)를 정형화된 도메인 객체(`GuestPreference`)로 변환합니다.

* **네트워크 오버헤드 최소화 (1-Call Batch Parsing)**:
  * 50건의 예약을 개별 HTTP 통신(50회)으로 처리하지 않고, Jackson 직렬화를 통해 **단 1회의 HTTP POST 요청(JSON Array)**으로 Gemini API에 전달합니다.
  * API 응답 시간: **50건 기준 약 15~16초 (건당 약 0.3초 수준)**, 분당 호출 수(RPM) 소모 1회 보장.
* **노이즈 필터링**:
  * 식음(F&B) 요청("밥이 먹고 싶은데요?"), 단순 안부 인사 등 객실 물리 속성과 무관한 텍스트는 자동으로 무선호(`NONE`, `false`)로 안전 필터링합니다.
